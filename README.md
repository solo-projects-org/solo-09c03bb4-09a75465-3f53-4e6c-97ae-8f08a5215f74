# 海豹照片重捕核对（Seal Photo Census Review）

两轮照片的闭种群数量估计：上传同一调查区**两轮各自去重**的编号清单和**跨轮疑似同只**
的编号对，逐对核对，实时给出 Chapman 估计的上下界，并推荐下一对最值得比对的照片。
核对结论保存在 SQLite 中。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据落在命名卷 `seal-data`（容器内 `/data/seals.db`）。网页首页有两个可一键载入的
样例（小样 12+11 个编号 / 6 对候选；中样 40+38 个编号 / 20 对候选），载入后直接点
“创建调查并开始核对”即可试用。

不使用 Docker 时：

```bash
python3 -m pip install -r requirements.txt
SEAL_DB_PATH=./seals.db python3 -m uvicorn app.main:app --port 8000
```

## 输入与规则

| 项 | 规则 |
|---|---|
| 每轮编号数 | ≤ 80，轮内必须已去重（重复直接报错） |
| 跨轮疑似对 | ≤ 800，同一对不能重复；两端编号必须出现在对应轮清单中 |
| 配对约束 | 每个编号最多配一次（合法配对=候选对上的一个匹配） |
| “同一只” | 必须出现在合法匹配中，且与已有“同一只”结论不能共用编号 |
| “两只” | 不允许出现在合法匹配中 |
| 其余候选 | 可配可不配 |

文件格式：编号清单每行一个（也接受空格/逗号/分号分隔）；疑似对每行
`第一轮编号,第二轮编号`（也接受 Tab、空格、`->`）。可直接粘贴或上传文本文件
（UTF-8 / GB18030）。编号允许字母、数字与 `_ . : / -`。

## 估计方法

n1、n2 为两轮去重编号数，m 为“两轮都拍到”的个体数（合法匹配的大小）：

```
N̂ = (n1 + 1)(n2 + 1) / (m + 1) − 1
```

N̂ 关于 m 严格递减，因此**在所有合法配对下**的上下界只取决于 m 的可达范围：

- m_min = 已核实的“同一只”对数（不含其它候选时的最小匹配）；
- m_max = m_min + 在未被占用的待核候选上的最大二分匹配（Hopcroft–Karp）；
- 估计区间 = [N̂(m_max), N̂(m_min)]。

## 推荐下一对

对每个“仍可配上”的待核候选（两端编号都还没被“同一只”结论占用）：

1. 试算判为**同一只**：强制该对入匹配，其余待核候选取最大匹配 → 区间 I_same；
2. 试算判为**两只**：禁止该对，其余待核候选取最大匹配 → 区间 I_diff；
3. 决策宽度 = max(width(I_same), width(I_diff))，取决策宽度最小的一对推荐。

并列为最优时全部列出（页面和 API 都会说明并列）。已被“同一只”结论占用端点的待核
候选在页面上标为“待核对（不可再配）”：它们只能判两只，不再影响估计与推荐。

## 提交结论与冲突

- 批量提交，**任何一对冲突则整批回滚**，原结论与用其算出的估计/推荐原样保留；
- 冲突包括：同一编号被判给两只“同一只”、已核实的对改判（同一只↔两只）、
  疑似对不在候选清单中；
- 重复提交相同结论是幂等的，不报错；
- 校验在 SQLite `BEGIN IMMEDIATE` 事务内对**当前已存结论**重做，两个并发的
  “同一只”提交只会有一个成功，另一个收到冲突提示。

## 接口

- `GET /` 首页（新建 + 样例 + 已有调查）
- `POST /surveys` 创建调查
- `GET /surveys/{id}` 核对页（估计、推荐、候选表、试算明细、已存结论）
- `POST /surveys/{id}/verdicts` 提交结论（表单字段 `verdict__<候选下标>`）
- `GET /api/surveys/{id}` JSON：`estimate` 与 `recommendation.trials/best`
- `GET /healthz` 健康检查

## 实现结构

```
app/model.py     纯领域逻辑：校验、冲突规则、Hopcroft–Karp、Chapman、试算与推荐
app/db.py        SQLite（surveys / candidates / verdicts），事务化结论写入
app/main.py      FastAPI 路由与表单解析
app/templates/   Jinja2 页面
samples/         网页可试用样例数据
tests/           pytest（领域 + HTTP）
tools/selfcheck.py  收尾自测脚本（争用、冲突、边界、样例、输入上限）
```

## 自测

```bash
python3 -m pytest          # 29 个测试
python3 tools/selfcheck.py # 打印逐项 PASS/FAIL
```

本机实测（Python 3.11，单核）：

- 29 个 pytest 全通过；`selfcheck.py` 全部 PASS。
- 上界/下界与穷举所有合法匹配的结果逐一吻合（60 组随机图 + 25 组带结论随机图）。
- 候选争用：80×80 编号、800 对候选的随机图，最大匹配 80，区间
  [80, 6560]（m=0 时 N̂=6560）。
- 800 对候选、全部待核时，一次完整试算（1600 次最大匹配）约 **0.5 s**；单次估计
  约 **1 ms**。中样（40+38、20 对）整页渲染约 **0.06 s**，创建调查约 **0.08 s**。
- 并发两条“同一只”结论抢同一编号：一条成功、一条冲突，库中只剩一条结论。
- 本地 uvicorn 跑通全流程：创建 → 推荐 → 提交 → 区间收窄（如 12+11 小样
  m∈[0,5] → 提交一对后 m∈[1,5]，区间 25～155 → 25～77；中样 40+38，
  提交一对后 87.83～1598 → 87.83～798.5）→ 冲突提交被拒且状态不变
  （“冲突：第一轮编号 B11 已与 C09 判为同一只，不能再与 C02 配对”，API 结果逐字段不变）。
- 边界页面：全部候选核实后区间收缩为点值且不再出现试算表；仍有待核候选但编号已被
  “同一只”占用时，页面提示它们“不可再配”，推荐列表为空而不是给出无效建议。

## 待办 / 已知限制

- 单进程 SQLite，适合普查组内部小规模使用；多副本部署需换成 Postgres 等。
- 结论目前不可改判（按“保留原结论”的规则设计）；如需撤销需另加审计与重开流程。
- 推荐只按“区间宽度最小”排序；如需按预计信息量（如假设“同一只”先验概率）排序，
  可再扩展目标函数。
- 未做登录与权限控制，部署到公网前应加认证。
- 上传文件为纯文本/CSV 编号清单，尚未支持从照片元数据自动抽取编号。
